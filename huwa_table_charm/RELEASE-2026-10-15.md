Products use price-on-request and are blocked from cart and checkout until a merchant supplies confirmed prices and inventory. ## Local

Run npm run migrate --prefix backend, then npm run catalog:release --prefix backend. Run npm run dev from the project root. Storefront: http://127.0.0.1:5175.

## Production

1. Set hosting domain and HTTPS reverse proxy. Copy .env.production.example to .env.production and populate three different random secrets (DB, access JWT, refresh JWT); JWTs must be at least 32 characters.
2. Back up the existing production database before applying migrations. Supply a persistent PostgreSQL volume; configure off-host backups through the hosting provider.
3. docker compose --env-file .env.production build
4. docker compose --env-file .env.production up -d db
5. docker compose --env-file .env.production run --rm backend npm run migrate
6. docker compose --env-file .env.production run --rm backend npm run catalog:release
7. docker compose --env-file .env.production up -d
8. Route the HTTPS domain to 127.0.0.1:8080. Confirm /api/health, product images, enquiry submission and protected admin inbox through the public domain.

Only the storefront is exposed on loopback; proxy it with your hosting provider's HTTPS ingress. API and database stay on the Compose network. Docker runtime verification requires Docker, which may not be available on this PC.

Do not advertise card checkout until the payment provider, shipping fees and local prices are configured and a live-provider test succeeds. Mock payment confirmation is disabled in production.
